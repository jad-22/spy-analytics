<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow_dispatch inputs -> runner shell | Inputs typed by whoever can dispatch; could carry shell metacharacters |
| GitHub secret -> runner process | API key materialises only inside the enrich step |
| runner -> public repo | Committed data is public |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-16 | Elevation / Tampering | backfill.yml script injection | mitigate | Inputs passed only through env vars and quoted "$VAR" args; job validates episode ids against regex + parquet; test enforces no `${{ inputs.` outside env lines |
| T-03-17 | Information Disclosure | backfill.yml key handling | mitigate | Secret only in the enrich step env; no set -x/printenv; GitHub masks secrets in logs; test asserts exactly one secret reference; nightly.yml has no key (OPS-03) |
| T-03-18 | Information Disclosure | committed data | mitigate | test_events_data.py and report leak scan reject sk-ant-, x-api-key, encrypted_content, cited_text in committed files |
| T-03-19 | Repudiation (reported numbers) | budget/enrichment docs | mitigate | Both docs generated by scripts with a do-not-hand-edit header; regeneration is diff-stable |
| T-03-20 | Denial of Service (budget) | repeated dispatches | mitigate | Ledger committed even on failure (`!cancelled()`), so the job's budget guard sees all prior spend; concurrency group prevents parallel paid runs |
| T-03-21 | Spoofing (who can dispatch) | workflow_dispatch | accept | Only repo collaborators with write access can dispatch; solo repo |
</threat_model>
