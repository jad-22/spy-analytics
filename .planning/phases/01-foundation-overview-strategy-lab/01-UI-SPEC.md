# Phase 1 — UI Design Contract

> Visual and interaction contract for the Overview and Strategy Lab pages. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker. Every token below is expressed as a Streamlit
> mechanism (`.streamlit/config.toml`, `st.plotly_chart(theme="streamlit")`, native widgets) —
> not as arbitrary CSS — because the stack has no component library to enforce one.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — pure Python/Streamlit app, not React/Next.js/Vite. The shadcn gate does not apply; there is no npm component registry in this stack. |
| Preset | not applicable |
| Component library | Streamlit native widgets only: `st.sidebar`, `st.columns`, `st.container(border=True)`, `st.metric`, `st.dataframe`, `st.tabs`, `st.toggle`, `st.slider`, `st.plotly_chart`. No custom component libraries, no CSS frameworks. |
| Icon library | Streamlit's built-in Material Symbols shorthand (e.g. `:material/trending_down:`) — used only for `st.Page(icon=...)` sidebar nav entries. No emoji anywhere in the app UI (distinct from any emoji policy on agent chat output). |
| Font | Streamlit theme `font = "sans serif"` (system UI stack: -apple-system, Segoe UI, Roboto, etc.). No custom font loading — keeps the app fast and avoids FOUC on Streamlit Cloud's cold starts. |

**Why no shadcn/CSS framework:** Streamlit renders its own DOM; injecting a component library or heavy custom CSS fights the framework and breaks on every Streamlit minor version bump. All visual control in this contract routes through `.streamlit/config.toml` `[theme]` keys (verified against current Streamlit docs: `primaryColor`, `backgroundColor`, `secondaryBackgroundColor`, `textColor`, `font`, `baseFontSize`, `chartCategoricalColors`, `chartSequentialColors`, `chartDivergingColors`) plus `st.plotly_chart(..., theme="streamlit")` (the default), which makes Plotly charts inherit the same theme tokens as the native widgets automatically. This is the one pattern CLAUDE.md implicitly expects ("design tokens expressed in terms Streamlit can actually enforce").

## Spacing Scale

Streamlit does not expose arbitrary pixel spacing — layout is container/column based. The
8-point scale below maps to the nearest real Streamlit mechanism; where Streamlit only offers
named sizes (not exact px), that is stated honestly rather than invented.

| Token | Value | Streamlit mechanism | Usage |
|-------|-------|----------------------|-------|
| xs | 4px | Not independently controllable — accepted as a sub-pixel rounding tolerance only, never hand-built | n/a |
| sm | 8px | `st.columns(n, gap="small")` (Streamlit-documented as the smallest named gap) | Tight groupings: a metric + its delta, a toggle + its label |
| md | 16px | Default vertical rhythm between consecutive `st.write`/widget calls (Streamlit's own block spacing); `gap="medium"` on columns | Default spacing between sidebar controls, between a chart and its caption |
| lg | 24px | `st.container(border=True)` internal padding (Streamlit's fixed container padding) | KPI card padding, Strategy Lab section cards |
| xl | 32px | `st.columns(n, gap="large")` | Gap between the KPI strip and the price chart; gap between Strategy Lab's equity chart and the metrics table |
| 2xl | 48px | `st.divider()` + one blank `st.write("")` spacer | Boundary between the headline callout ("0 of 24 rules beat buy-and-hold") and the controls below it |
| 3xl | 64px | Not used — no page needs a break this large at single-page-per-view granularity | n/a |

Exceptions:
- `st.sidebar` padding is fixed by Streamlit (not themeable) — accepted as-is, do not fight it with custom CSS.
- `st.metric` internal label-to-value spacing is fixed by Streamlit — do not override with CSS injection (see Design System rationale).

## Typography

Streamlit does not expose per-element font-size/weight the way CSS does. The contract below
declares the **only four text roles this app uses** and the **exact Streamlit or Plotly
mechanism** that produces each — so the executor has zero ambiguity about which API call maps
to which role.

| Role | Size | Weight | Line Height | Mechanism |
|------|------|--------|-------------|-----------|
| Body | 16px | 400 (regular) | 1.5 | Streamlit default body text (`st.write`, `st.markdown`, widget labels). Set explicitly via `[theme] baseFontSize = 16` in `.streamlit/config.toml` (do not leave implicit). |
| Label / caption | 14px | 400 (regular) | 1.4 | `st.caption()` for metadata: "as of" timestamps, chart source notes, the "coincident, not causal"-style disclaimers that appear later; also Plotly axis ticks/legend text (`layout.font.size = 12`, inherited from `theme="streamlit"`) |
| Heading | 20–24px | 700 (bold, via Markdown `##`/`###` or `st.subheader`) | 1.2 | `st.header()` (page section titles: "Overview", "Strategy Lab") and `st.subheader()` (subsection titles: "Largest drawdowns", "Short × long grid"). Do not use more than these two heading levels in Phase 1. |
| Display | 28–36px | 700 (bold, `st.title()` default) | 1.15 | `st.title()` once per page (page name) and the single LAB-09 headline callout ("0 of 24 rules beat buy-and-hold") rendered via `st.markdown("## 0 of 24 rules beat buy-and-hold")` directly under the title, not inside a metric. |

Declared exactly 4 sizes and exactly 2 weights (400, 700), per the template's limit. `st.metric`'s
internal value/label typography is fixed by Streamlit itself and is accepted as a fifth,
non-negotiable size the app does not control — documented here so the checker does not flag it
as a contract violation.

## Color

Base theme is **light** (`[theme] base = "light"`) — a finance dashboard for a public portfolio
reads as more professional and prints/screenshots better in light mode than dark, and it is
Streamlit's lower-risk default across embedding contexts (recruiter browsers, LinkedIn preview
images). This is a default, not a requirement surfaced in CONTEXT.md — flagged as such.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`backgroundColor`) | Main content area background on both Overview and Strategy Lab |
| Secondary (30%) | `#F0F2F6` (`secondaryBackgroundColor`) | Sidebar background, `st.container(border=True)` card fills (KPI strip cards, metrics-table card) |
| Accent (10%) | `#1A5FB4` (`primaryColor`, a mid-blue) | Reserved for: the selected/active state of sidebar toggles and sliders, `st.button(type="primary")` (none planned in Phase 1 — see Copywriting), the strategy equity-curve line in the Overview/Strategy Lab Plotly charts, and link text. Streamlit applies `primaryColor` globally to all interactive-control accents (slider track/handle, selected radio/checkbox, tab underline) — this is a Streamlit platform behavior, not a per-element choice, and is documented here so the checker doesn't expect finer-grained scoping than the framework allows. |
| Destructive | not applicable | Phase 1 has no destructive actions — it is a read-only app with no delete/overwrite/submit-and-confirm flows (sidebar controls only filter/recompute views). No destructive color is declared. |

**Domain-specific semantic colors** (beyond the 60/30/10 UI split — these color financial data,
not UI chrome, and are set as explicit Plotly trace colors, not theme tokens):

| Signal | Value | Usage |
|--------|-------|-------|
| Gain / positive | `#1A7F37` (green) | Positive KPI deltas (`st.metric(delta_color="normal")` default already maps positive→green, negative→red — reuse, do not override), positive forward-return cells |
| Loss / negative | `#C0152F` (red) | Negative KPI deltas, drawdown shading base color, negative heatmap cells |
| Buy-and-hold baseline | `#6B7280` (neutral gray) | The buy-and-hold equity line on every equity chart — must visually read as "the baseline being compared against," never the accent blue |
| Strategy line | `#1A5FB4` (same as accent) | The selected rule's equity line — the one thing on the chart the accent blue is "spent" on, per LAB-03 |
| Drawdown regime shading | `#C0152F` at opacity 0.08 / 0.15 / 0.25 | Three nested `vrect`/shape bands for −5%, −10%, −20% drawdown regimes (OVER-03) — deepest drawdown gets the darkest band, never three unrelated hues |
| Heatmap diverging scale | `theme.chartDivergingColors` (red–white–green, centered at 0) set in `.streamlit/config.toml`, consumed automatically by `st.plotly_chart(theme="streamlit")` | LAB-05 short×long excess-return heatmap — center must be white/neutral at exactly 0% excess return, red below, green above, so "no edge" reads as visually blank, not as a color choice |

Accent reserved for: strategy equity line, active/selected control state (Streamlit-enforced), and link text. Never used for body text, card backgrounds, or static chart gridlines.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None in Phase 1.** All sidebar controls (date range, price basis toggle, MA type/period pickers, cost slider, split date) are reactive — Streamlit reruns and updates charts immediately on change, per the existing `st.sidebar` pattern in SPEC.md. There is no "Run backtest" submit button; recomputing the 24-rule grid over ~4,000 cached rows is fast enough (local DataFrame ops, no network) to stay reactive. If a future profiling pass shows the heatmap/rolling-start/IS-OOS recompute is slow enough to need debouncing, wrap those three in `st.form(..., border=False)` with a button labeled **"Update grid"** — not before it's proven necessary. |
| Headline callout (LAB-09, verbatim) | `## 0 of 24 rules beat buy-and-hold` directly under the Strategy Lab `st.title()`, followed by one `st.caption()` line: *"Every SMA/EMA crossover tested — including the notebook's old favorite, EMA10 vs SMA200 — trails a simple buy-and-hold on this window, any price basis, any cost setting."* This is non-negotiable per LAB-09 and `docs/PHASE0_FINDINGS.md`; it must lead the page, not be buried below the controls. |
| Sidebar control labels | "Date range" (range slider/date inputs), "Price basis" with options **"Total return"** / **"Price only"** (OVER-06 — label the total-return option first since it's the honest default per SPEC.md), "Chart type" with options **"Line"** / **"Candlestick"**, "Moving averages" (multiselect: SMA 20 / EMA 20 / SMA 50 / etc.), "Drawdown regimes" toggle group (−5% / −10% / −20%), "Short MA", "Long MA", "200D trend filter" toggle, "Trading cost (bps)" slider, "Split date" (IS/OOS). Use sentence case, no trailing colons, no question marks. |
| Empty state heading | **"No market data yet"** — shown only if `data/prices.parquet` is missing or `meta.json` fails to load (e.g. first deploy before the nightly job has ever run). |
| Empty state body | *"SPY price history hasn't been loaded yet. This updates automatically after the next scheduled refresh — check back after today's US market close."* No retry button (there is nothing to retry client-side; this is a read-only app). |
| Error state (insufficient history for a rule) | *"Not enough price history for this rule in the selected date range. Try an earlier start date or a shorter moving-average period."* — triggered when the chosen start date leaves fewer bars than the slower MA's period requires (the exact bug class fixed in Phase 0's `core/grid.py` off-by-one). Shown via `st.warning()`, not a hard crash. |
| Error state (stale data) | *"Data was last refreshed {last_refresh}. If this looks out of date, the nightly job may have failed — the app is still showing the last good snapshot."* Shown as `st.caption()` under the page title whenever `meta.json`'s `last_refresh` is older than 3 calendar days (covers weekends + one missed run without false-alarming every Monday). |
| Destructive confirmation | Not applicable — Phase 1 has no destructive actions. |

## Streamlit-Specific Contract (supplements the template — required for this stack)

Because the UI-SPEC template is written for component-library stacks, the following
Streamlit-only decisions are recorded here so the planner/executor have one authoritative
source instead of re-deriving them mid-build:

1. **Navigation:** Use `st.navigation` + `st.Page` (per CLAUDE.md's correction to SPEC.md's
   literal `pages/` directory sketch). Define pages in `app/Home.py`: `st.Page("app/pages/1_overview.py", title="Overview", icon=":material/show_chart:")` and `st.Page("app/pages/2_strategy_lab.py", title="Strategy Lab", icon=":material/science:")`. Do not mix this with a `pages/` auto-discovery directory — Streamlit locks into whichever pattern is used first.
2. **Caching:** Every `core/storage.py` reader uses `@st.cache_data` with **no `ttl`** (per
   CLAUDE.md's override: each nightly commit redeploys the app and clears the whole cache, so a
   TTL only adds staleness risk with no benefit). Cache key is the filename; do not pass mutable
   DataFrames across cached function boundaries.
3. **Charts:** Every `st.plotly_chart(fig, theme="streamlit")` — never `theme=None`. This is
   what makes `chartCategoricalColors`/`chartSequentialColors`/`chartDivergingColors` from
   `.streamlit/config.toml` apply automatically, keeping native widgets and Plotly charts in the
   same palette without hand-building a Plotly template per chart.
4. **KPI strip layout (OVER-04):** Four `st.columns(4, gap="medium")`, each containing one
   `st.container(border=True)` wrapping one `st.metric()`. Let `st.metric`'s built-in
   `delta_color` (green positive / red negative) stand in for the Gain/Loss semantic colors
   above — do not duplicate that logic manually.
5. **Drawdown table (OVER-05):** `st.dataframe` with `column_config` for percentage/date
   formatting — not a hand-built HTML table. Keep it inside a `st.container(border=True)` card
   matching the KPI strip's visual weight.
6. **No custom CSS injection.** If a visual requirement in this contract cannot be met through
   `.streamlit/config.toml` or a native widget parameter, flag it back to the UI checker rather
   than reaching for `st.markdown("<style>...</style>", unsafe_allow_html=True)` — CSS hacks
   break silently across Streamlit version bumps and this app has no test coverage for DOM
   structure.

### `.streamlit/config.toml` — authoritative values for Phase 1

```toml
[theme]
base = "light"
primaryColor = "#1A5FB4"
backgroundColor = "#FFFFFF"
secondaryBackgroundColor = "#F0F2F6"
textColor = "#262730"
font = "sans serif"
baseFontSize = 16
chartCategoricalColors = ["#1A5FB4", "#6B7280", "#1A7F37", "#C0152F"]
chartDivergingColors = ["#C0152F", "#FFFFFF", "#1A7F37"]
```

(`chartSequentialColors` is left unset for Phase 1 — no sequential-only chart exists yet;
revisit if Phase 4's severity-sized markers need one.)
