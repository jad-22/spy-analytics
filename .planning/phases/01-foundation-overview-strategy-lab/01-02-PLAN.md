core/market_calendar.py: a pure module, no network. Define class NYSEHolidayCalendar(AbstractHolidayCalendar) with these rules:
- New Year's Day: Holiday month=1 day=1, observance sunday_to_monday. NYSE does not close the prior Friday when Jan 1 is a Saturday.
- MLK: USMartinLutherKingJr restricted to start_date 1998-01-01.
- USPresidentsDay, GoodFriday, USMemorialDay.
- Juneteenth: month=6 day=19, start_date 2022-01-01, observance nearest_workday.
- Independence Day: month=7 day=4, observance nearest_workday.
- USLaborDay, USThanksgivingDay.
- Christmas: month=12 day=25, observance nearest_workday.

NYSE_SPECIAL_CLOSURES is a tuple of ISO dates, each with a trailing comment naming the event:
- 1994-04-27 (Nixon funeral)
- 2001-09-11, 2001-09-12, 2001-09-13, 2001-09-14 (September 11)
- 2004-06-11 (Reagan funeral)
- 2007-01-02 (Ford funeral)
- 2012-10-29, 2012-10-30 (Hurricane Sandy)
- 2018-12-05 (G.H.W. Bush funeral)
- 2025-01-09 (Carter funeral)

nyse_holidays(start, end) is the calendar's holidays plus the special closures inside [start, end]. nyse_sessions(start, end) is pd.bdate_range(start, end).difference(nyse_holidays(start, end)).

core/validate.py: no Streamlit, no network. It imports nyse_sessions and the data COLUMNS. validate_snapshot(new, old, cfg) raises ValueError with a descriptive message per D-13 branch, in this order:
1. If old is not None and len(new) < len(old): "row count shrank from {old} to {new}".
2. If old is not None and new.index[-1] < old.index[-1]: "last date moved back".
3. On the overlap of old and new, for each of open, high, low, close, volume: if abs(new/old - 1) > cfg.rewrite_tolerance_pct for any row, raise "{col} rewritten beyond tolerance on {n} rows, first {date}". For volume, compare on rows where old volume > 0.
4. adj_close: ratio = new/old on the overlap. If ratio.max()/ratio.min() - 1 > cfg.adj_close_factor_tolerance_pct, raise "adj_close restated by more than a single common factor".
5. Gap check on the whole new frame: missing = nyse_sessions(new.index[0], new.index[-1]).difference(new.index). If any are missing, raise "missing session(s): {first 10 dates}".

drop_incomplete_session(df, now_utc, cfg): convert now_utc to America/New_York. If df.index[-1].date() equals today's ET date and the ET time is earlier than cfg.session_complete_after_et, return df.iloc[:-1]. Otherwise return df unchanged.

Run test_committed_snapshot_has_no_missing_sessions against the real 1993+ snapshot from Plan 01. If it reports missing dates:
- Research each date. A date is a genuine NYSE full-day closure only if a cited source (NYSE or SEC notice, or a news report of the closure) confirms it. In that case add it to NYSE_SPECIAL_CLOSURES with a comment naming the event and source.
- If it is a real trading day that Yahoo is missing, do NOT add it as a holiday. Stop and record it in the SUMMARY as a blocker needing a decision, because DATA-03 would fail every nightly run.
Never relax the gap check to make the test pass.

Commit as test(01-02) and then feat(01-02).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Yahoo Finance → validate_snapshot | Untrusted, possibly restated or partial data |
| GitHub Actions runner → repo (push) | Automated write access to a public repo |
| Fork PRs → workflows | Untrusted code could run with repo permissions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | core/validate.py | mitigate | The D-13 gate covers shrink, last-date regression, OHLCV rewrite > rewrite_tolerance_pct, non-common-factor adj_close, and missing NYSE sessions. One test per branch. |
| T-01-06 | Tampering | partial intraday bar | mitigate | drop_incomplete_session removes today's bar before session_complete_after_et (US/Eastern) |
| T-01-07 | Elevation of Privilege | nightly.yml | mitigate | Triggers limited to schedule + workflow_dispatch (no pull_request_target), permissions are contents: write only, the default GITHUB_TOKEN is used with no PAT, and concurrency stops overlapping pushes |
| T-01-08 | Denial of Service | ci.yml loop | mitigate | The GITHUB_TOKEN push does not trigger workflows, and paths-ignore data/** is defense in depth (OPS-05) |
| T-01-09 | Repudiation | data commits | accept | Bot commits carry the github-actions[bot] identity and the run log. A manual commit that bypasses the job is a documented residual risk (RESEARCH Security Domain); there is no branch protection in scope. |
| T-01-10 | Tampering | third-party actions | accept | Only GitHub-owned actions/checkout@v4 and actions/setup-python@v5, matching the existing ci.yml. No third-party commit action (RESEARCH recommends a hand-rolled git step). |
</threat_model>
